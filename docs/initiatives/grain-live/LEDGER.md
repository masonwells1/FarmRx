## GL-000 — Initiative context and GL-1 plan

- **Date/time:** 2026-09-15 09:45 -05:00 (`America/Chicago`).
- **Authority:** the `Initiative GL — Grain Live` section of the 2026-09-05 owner amendment in `docs/GOAL.md` (GL-1 USDA MARS basis feed), decision 2 of that amendment (Barchart declined; the USDA AMS My Market News feed is public-domain government data and is authorized), and the `USDA AMS MARS basis feed` section of `docs/grain-live-design.md`. Mason approved planning and building GL-1 in the working session on 2026-09-15 ("Plan and build GL-1") after FD-2 merged into `main` as `396a9e8` (front-door ledger FD-032). Merge, live migration, secrets, and scheduling remain Mason's decisions.
- **Starting point:** branch `claude/app-improvement-strategy-kzqk6s` restarted from `origin/main` `396a9e8`. Today the only feed fence is the browser's `isMarsBid`, which recognizes exactly the `[USDA MARS 2850]` notes prefix; no SQL fence, no feed provenance column, no farm region, no edge function, and no workflow exist. The alert sweep (`run_scheduled_alert_sweep`, migration 0039) takes the newest cash bid for a commodity regardless of source; GL-2 owns that split and is not touched here.
- **Tier:** full (a migration with a new table, new columns, a unique constraint, a `SECURITY DEFINER` ingestion function, row-level policy changes on `cash_bids`, a new edge function, and scheduler secrets). Disposable-database assertions, fresh-context review of the exact commit (Codex reviews the pull request), and the role matrix apply.
- **What this sandbox cannot do (recorded, not assumed):** outbound requests to `marsapi.ams.usda.gov` and `mymarketnews.ams.usda.gov` are refused by the session's network policy (HTTP 403 from the proxy on 2026-09-15). The geography of report 2850 and the exact shape of its rows therefore cannot be verified from here. GL-1 is built so that nothing is written until both are verified: the report-to-geography mapping is a server-side configuration row with a `verified_at` stamp that is null on seed, the ingestion function refuses an unverified report, and the parser skips every row whose fields it does not recognize while recording the field names it saw. Verifying 2850 (or an Illinois/Indiana report) against the USDA listing and stamping it is a live-data action for Mason, recorded in this ledger when it happens.
- **Plan (one tranche, one commit):**
  1. **Migration `20260915150000_gl1_usda_mars_feed.sql`.**
     - `farms.market_region text` (null or a two-letter uppercase US state code, checked). No default. Nothing infers it from field states or addresses. Writable through the existing `farms_update` policy (`can_manage_farm`: owner or manager), so a worker or rep cannot set it.
     - `public.usda_market_reports`: the verified mapping from a USDA report id to the geography it covers (`report_id`, `name`, `geography` state code, `geography_label`, `verified_at`, `verification_note`). Read-only for signed-in users (so the Grain page can say which reports cover the farm's region and whether they are verified); written only by the service role. Seeded with report 2850 as "Iowa Daily Cash Grain Bids", geography `IA`, `verified_at` null, and a note saying what verification is owed.
     - `public.usda_market_report_runs`: the service-only run log (report, report date, started/finished, status `ok`/`skipped`/`failed`, fetched/written/unchanged/skipped counts, farms written, detail without secrets). A successful run for a report and market day lets the next run skip the fetch ("once per market day, cached server-side").
     - `cash_bids` gains `feed_source`, `feed_report_id`, `feed_geography`, `feed_observation_key`, all null on a farmer's row and all set on a feed row (checked together); a unique index over `(farm_id, feed_observation_key)` on feed rows. The `cash_bids_insert` and `cash_bids_update` policies gain `feed_source is null`, so a signed-in client can neither create a feed row nor turn one into a manual bid; the service role, which bypasses row-level security, writes feed rows only through the function below.
     - `public.ingest_usda_mars_observations(p_report_id, p_run_id, p_observations jsonb)`: `SECURITY DEFINER`, fixed `search_path`, executable by the service role only (revoked from public, anon, authenticated). Refuses an unknown or unverified report. Fans each validated observation into every farm whose `market_region` equals the report's geography (a farm without a region receives nothing) by transactional upsert keyed on `(farm_id, feed_observation_key)`; an unchanged row is left untouched (its `updated_at` does not move, so a retried run cannot change which row the sweep sees as newest). Rows carry the provenance note `[USDA MARS <report-id> · <geography label>]`. Returns counts.
  2. **Edge function `usda-mars-feed`** with the pure logic in `supabase/functions/_shared/marsFeedLogic.ts` and `marsFeedOrchestrator.ts` (regressions beside them, run by `npm run regression`). Same scheduler authorization as the alert sweep (`x-scheduler-key`), MARS API key from the `USDA_MARS_API_KEY` secret via HTTP Basic auth, never logged or returned. For each verified report: skip when today's market day already has an `ok` run; fetch with a deadline; parse with an explicit commodity whitelist (Corn → `corn_yellow`, Soybeans → `soybeans`, Wheat → `wheat`), finite numbers, plausible basis, a deterministic observation key (report id, USDA row identity, bid date, location, commodity, delivery window; hashed when long); skip and count anything else, recording the field names seen; call the ingestion function; write the run row. A failure writes a `failed` run and leaves history untouched; nothing is ever written under today's date from yesterday's rows.
  3. **Workflow `.github/workflows/usda-mars-feed.yml`**: weekday runs at 4:30 PM and 7:00 PM Chicago (both offsets, so two UTC hours each), `workflow_dispatch`, the same secret names pattern as the alert sweep plus the feed URL. The function is idempotent, so the extra offset hour is harmless.
  4. **Browser.** `isMarsBid` recognizes any MARS provenance (`feed_source = 'usda_mars'` or a `[USDA MARS …]` note), so no feed row from any report enters position, revenue, plan, alert-candidate, or Today math. `CashBid` carries the feed columns (read tolerantly, so cached rows still load). The Grain basis history names each feed row's report and geography ("USDA MARS 2850 · Iowa, display-only; last dated …") and keeps the "Basis feed unavailable — last updated …" wording. The farm settings page (today's "Farm privacy" page at `/privacy`, retitled "Farm settings" with the privacy card unchanged) gains a "Market region" card for owners and managers: a state picker with no default and a plain sentence naming the verified USDA reports that cover it or saying none is verified yet; saved through a new farm settings repository that mirrors the privacy toggle (online only, context verified before and after, the returned row confirmed). The Grain page says in plain words when the farm has no region.
  5. **Guards and proof.** Static guards pin the migration's fences (the revoke on the ingestion function, its fixed search path, the `feed_source is null` policy checks, the unique feed index) and the foundation lane's Deno check of the new function; the mutation drill gains mutations for those needles. Disposable-database assertions (`scripts/sql/gl1-mars-feed-assertions.sql`, run by both disposable lanes): an unverified report writes nothing; a verified report fans into two Iowa farms and not into an Illinois farm or a farm without a region; a retried identical run adds no row and moves no `updated_at`; a changed basis updates in place; a signed-in owner cannot insert a feed row or edit one; an owner can set a valid region and cannot set an invalid one; a worker cannot set it; a worker without financial access reads zero feed rows; a signed-in user cannot call the ingestion function. Browser journeys: the owner sets the region and reads the report sentence; the basis card labels a feed row; the worker without financial access still sees no grain row.
- **Deliberately out of scope:** GL-2's alert split and crop-year eligibility; any USDA report other than the seeded 2850 row; any change to contract, bin, delivery, or on-hand math; live enablement (applying the migration, setting `USDA_MARS_API_KEY` and the scheduler secrets, adding the workflow secrets, stamping a report verified).
- **Rollback path:** revert the GL-1 commit; the migration is additive (new table, new nullable columns, new function, policy predicates that only narrow client writes) and can be reversed by a follow-up migration that drops them. No stored row is changed by the migration itself.
