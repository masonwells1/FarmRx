- **Findings (Codex, on `fc86073`):** (P1) one shared submit lock across every position card let a slow save on one card silently drop a commit on another, leaving that limit dirty with no retry; (P1) a second debounced carry edit could start its save before the returned `updated_at` reached the calculator, so it would send the old version and conflict.
- **Dispositions:** the lock is now keyed per position scope, the commit reads the workspace through a ref that is updated synchronously with the saved row, and when the farmer kept typing while a save was in flight the newest value is committed once more after the lock releases. The carry version race was already closed in `65943b1`, where the calculator updates its remembered version from the returned row inside the chained save itself, before the next queued save can start; recorded here as already repaired rather than reopened.
- **Proof:** `npx tsc -b --force` exit 0; Grain receipt and Supabase grain regressions passed; `npm run build` exit 0; `git diff --check` clean.

- **Date/time:** 2026-09-13 15:55 -05:00 (`America/Chicago`).
- **Findings (Codex, on `b3f3a2b`):** (P1) the write policies required only `can_edit_farm`, so an active worker without financial access could insert or change these private grain settings through the Data API even though the screen is closed to them; (P1) the storage-mode buttons had no flush of their own, so a mode change made within the pause and followed by a farm switch was lost.

The mode buttons now save as soon as React has committed the click. While re-proving, the harness showed that this immediate flush also fired in legacy (device-only) mode, so both flush functions now return early unless the farm's tables are live; the legacy run again records zero farm saves and one `localStorage` key.
- **Proof:** `scripts/verify-fs-persist-disposable.sh` printed `FS_PERSIST_DISPOSABLE_PASS`; `npx tsc -b --force` exit 0; Grain receipt, Supabase grain, and grainSettings regressions passed; `npm run build` exit 0; `git diff --check` clean; browser harness unchanged on desktop and phone (five saves in the expected order, remote resync, blur flush within 60 ms, no errors) and legacy mode back to zero saves.
